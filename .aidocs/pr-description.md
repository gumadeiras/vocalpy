Problem

The docs landing page had drifted into a second README copy. That left the docs
site with duplicated installation text, duplicated badges, and its own version
string that no longer matched the packaged project version.

Mental model

The repo should have one canonical install/usage narrative in the root README.
The docs site should act as a concise landing page that points readers to the
maintained operational surfaces: package validation commands, fixture guidance,
and autogenerated API reference pages.

Non-goals

- No runtime behavior changes
- No notebook or example fixture changes in this slice
- No Sphinx theme or build-pipeline changes

Tradeoffs

Linking the docs landing page back to GitHub markdown keeps the repo with one
source of truth for installation and notebook curation, but it does mean some
top-level docs content lives outside the rendered Sphinx site.

Architecture

- `docs/index.md` is now a real landing page instead of a README clone
- `docs/conf.py` now derives `release` from `vocalpy.__version__`
- the docs landing page points to:
  - root README for install/package narrative
  - `examples/README.md` for maintained-vs-archived notebook guidance
  - `examples/audios/README.md` for fixture contract details

Observability

- `python -m sphinx -b html docs docs/_build/html`
- inspect rendered `docs/_build/html/index.html`
- verify the reported docs version follows `vocalpy.__version__`

Tests

- Sphinx HTML build
